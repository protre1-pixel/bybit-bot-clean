# 2026-08-19 배포: SQUEEZE_ENTER_MULT/BREAKOUT_MULTIPLIER 완화 (0.7/1.6 → 0.85/1.3)

## 배경

사용자가 실제 라이브 차트에서 봇의 진입 시점이 원하는 지점(하늘색 화살표)보다 계속 늦다는
점을 지적 (`backtest_archive/2026-08-18_leverage5_3h_hold_16sl_deploy.md` 배포 이후).
원인 진단 결과 두 가지가 겹쳐 있었음:

1. `apply_entry_filters()`의 가격 정배열 필터 (2026-08-16 추가, 진입 직후 즉시 역배열
   청산되는 whipsaw 방지 목적) — 이건 이번에 건드리지 않음.
2. `SQUEEZE_ENTER_MULT=0.7` / `BREAKOUT_MULTIPLIER=1.6`이 너무 타이트해서, 스퀴즈 인정
   자체가 늦고 브레이크아웃 발동에 필요한 확장폭도 커서 진입이 지연됨.

사용자 요청으로 2번 레버(sq/bo)를 완화하는 테스트를 진행.

## 이번 배포 결정

사용자가 "진입 시점이 제일 큰 문제"라며, 레버리지/홀드시간/SL은 그대로 두고 **sq/bo 값만**
반영해서 배포하라고 지시. 즉 35차 조합(SQ0.85/BO1.3 + 레버5x/홀드3h/SL16% — 34차와 동일한
리스크 구조 위에 진입 임계값만 완화) 그대로 라이브 반영.

### 변경 내용

`app/services/trading_service.py`:
```python
BREAKOUT_MULTIPLIER = 1.6 → 1.3
SQUEEZE_ENTER_MULT   = 0.7 → 0.85
```
레버리지(5x), `HOLD_WINDOW_SEC`(3h), `HOLD_CAT_SL_PCT`(16%) 등 나머지는 전부 그대로 유지.
`FAST_BREAKOUT_LOOKBACK`도 그대로(=2)이며 `fast_breakout_mult=None`이라 `BREAKOUT_MULTIPLIER`를
그대로 재사용하므로, 스퀴즈 경유 경로/fast_breakout 경로 둘 다 1.3배로 완화됨.
