# 2026-09-05 배포: BTC 모멘텀 게이트 (조용한 장 진입 차단)

## 배경

사용자가 현재 전략의 가장 큰 문제로 "익절은 대부분 0.5% 안팎으로 작은데, 손실은 한 번
나면 그동안의 익절을 다 잡아먹을 만큼 크다"는 점을 지적하고, "장이 좋을 때만 거래하는
게 낫지 않냐"는 아이디어를 제시. ADX 필터/regime-홀드 등 과거 실험은 이미 실패로
확인된 상태였고, 레버리지·포지션 사이즈를 사전에 줄이는 방안은 "어떤 거래가 손실 날지
미리 알 수 없다"는 이유로 기각. 대신 사용자가 "BTC가 크게 움직일 때만 = 장이 활발할
때만, 전 코인 진입 허용"이라는 시장 필터를 과감하게 테스트해보자고 제안.

## 정의 (AskUserQuestion으로 확정)

- BTC 등락률 = 직전 4시간(16캔들, 15분봉) 종가 대비 현재 종가 등락률
- `|등락률| >= 1.0%`면 그 시각엔 전체 코인(BTC 포함) 롱/숏 무관 신규 진입 허용, 아니면 전부 차단
  - 방향 연동 안 함 - BTC가 오르든 내리든 "크게 움직였다"는 사실 자체만 게이트로 사용(박스권 필터에 가까움)

## 변경 내용

`backtest_archive/backtest_current_live.py`: `run_backtest()`에 순수 게이트 파라미터
`entry_gate_ts` 추가(기존 로직 안 건드림 - 신호가 떠도 해당 시각이 게이트 밖이면
진입만 취소). MAE(Max Adverse Excursion) 기록용 필드(`worst_price`/`mae_pct`)도 이번
세션에서 함께 추가됨(별도 SL캡 실험용, 이 배포와는 무관하지만 같은 커밋에 포함).

`app/services/price_service.py`: `is_btc_momentum_gate_open()` 추가. BTCUSDT 15분봉을
조회해 직전 4시간(16캔들) 등락률을 계산하고 `|1.0%|` 이상이면 True 반환. 완성 캔들
단위로만 재계산(캐싱)해서 코인마다·폴링(2초)마다 API를 새로 호출하지 않도록 처리.
데이터 조회 실패 시엔 안전하게 마지막 캐시값(초기값 True=게이트 열림)으로 폴백.

`app/services/trading_service.py`: `auto_trade()`에서 `check_entry_signal()`로 신호를
얻은 직후, 실제 주문 직전에 게이트를 한 번 더 확인 - 신호가 있어도 게이트가 닫혀있으면
`signal = None`으로 취소. 기존 신호 판정/청산 로직에는 전혀 관여하지 않음(신규 진입만
차단).

  테스트 기준) - 코인별 추가 필터는 아직 미검토.

  거래 빈도 급감을 지켜보면서 필요시 임계값 재조정 가능.
