# 2026-08-21 배포: PROFIT_LOCK_RATIO 1.0 → 0.8 (장 좋을 때 트레일링 여유 실험)

## 배경

BTC를 비롯해 대부분 코인이 HMA200/HMA600 정배열이 뚜렷한 상승 추세를 타고 있는 상황에서,
사용자가 실시간 차트(200/600일선 정배열이 깔끔한 상승 구간)를 보여주며 "처음에 사서 그냥
들고 있었으면 지금보다 수익이 더 좋았을 것"이라고 지적. 이에 대해 이미 두 가지 관련 실험이
있었음을 먼저 확인/공유함:

1. **순수 regime 트레일링**(`test_pure_regime_trail_xrp_1y.py`) / **하이브리드**
   (`test_regime_trail_after_profit_xrp_1y.py`): "정배열 뒤집힐 때까지 무조건 홀드" 방식은
   XRP 1년 백테스트에서 MDD 99.9~100%, 복리 -99.94~-99.98%(계좌 사실상 증발)로 대참사 확인.
   HMA200/600 반전이 lagging 신호라 실제 반전 시점엔 이미 크게 밀린 뒤였음.
2. 사용자는 "그건 추세 꺾일 때까지 들고 가니까 그런 거고, 내가 같이 보면서 트레이딩하면
   그런 수익률은 안 나온다"며 위 regime-홀드 실험과는 별개로, **`PROFIT_LOCK_RATIO`를
   1.0→0.8로 낮춰서(고점 대비 20% 반납 쿠션)** 지금 장에 맞춰 실거래로 바로 테스트해보자고
   요청. "지금 기회"라며 즉시 반영 요청.

## 사전 고지 (배포는 그대로 진행)

`PROFIT_LOCK_RATIO`는 regime-홀드와는 별개로 이미 순수 스윕 백테스트(0.5/0.7/0.85/0.9/1.0,
4코인×1년, `backtest_archive/2026-08-17_profit_lock_ratio10_deploy.md` 등)가 있고, 0.7/0.9
둘 다 1.0보다 PF/MDD 전부 열세였음(예: BTC PF 1.16(0.9)/0.98(0.7) vs 1.23(1.0), MDD
50.9%/65.4% vs 42.4%). 0.8은 단독 스윕 기록은 없지만 이 사이 값이라 비슷한 경향(1.0보다
열세) 가능성이 높다는 점을 배포 전 사용자에게 알림. 사용자는 이를 인지한 상태로, 실거래
(paper/DEMO, 실자금 아님) 환경에서 지금 장세로 직접 검증해보길 원해 그대로 진행.

## 변경 내용

`app/services/trading_service.py`:
```python
PROFIT_LOCK_RATIO = 1.0 → 0.8
```
`PROFIT_LOCK_TRIGGER_PCT`(0.5%) 등 다른 상수는 그대로 유지. 이 값은 `trend_follow` 단계에서
최고수익(peak_profit_pct)이 트리거(0.5%)를 넘은 �이후 "최고수익 × ratio"를 무조건 지키는
반납방지 SL 하한선을 계산하는 데 쓰임 - 0.8로 낮추면 고점 대비 20%까지는 반납을 허용해
트레일링에 좀 더 여유를 줌(1.0은 반납 0%, 고점 근처에서 즉시 청산).

## 배포 절차

1. 배포 전 오픈 포지션 확인: 양쪽 인스턴스 모두 `dot` long 포지션 보유
   (entry=0.8489, profit_mode=trend_follow) - bot1 `mode=paper`, bot2 `BYBIT_DEMO=true`
   (Demo API, 실자금 아님) 확인. 이 변경은 SL 트레일링 계산에만 영향, 포지션 관리 로직
   자체는 안 건드려 오픈 포지션 있는 상태로 그대로 진행.
2. 서버(`192.168.1.134`, user `protre`)에서 `bybit-bot1`/`bybit-bot2` 양쪽
   `app/services/trading_service.py`를 `.bak_20260821_102626`로 백업.
3. 로컬 수정 파일 scp 배포 → 양쪽 `python3 -m py_compile` 통과 확인, 값(`PROFIT_LOCK_RATIO
   = 0.8`) 반영 확인.
4. `pm2 restart bybit-bot1 bybit-bot2` → 둘 다 online, 에러 없이 정상 기동(LIVE API/DEMO API
   연결 로그 확인). 기존 `dot` 오픈 포지션(entry/SL/profit_mode 전부) 재시작 후에도 그대로
   유지됨 확인.
