실제 Bybit 1분봉 히스토리(공개 kline API)로 각 거래의 기록된 진입/청산가를 교차검증한 결과:

  즉 실시간 시세가 아니라 **이론상 SL 목표가를 그대로 체결가로 기록**하고 있었음.
- 이 자체는 STALL-EXIT뿐 아니라 일반 SL/trend_follow SL 전체에 공통된 구조적 문제였음
  (TP는 원래도 `current_price`를 썼는데, SL만 목표가를 그대로 썼음 - 비대칭).
- 실제 시세로 재계산한 결과, 폴링 지연 때문에 감지 시점 실제가가 이미 이론가를 크게
  넘어선 경우(BNB/ADA/SOL) 기록된 손실이 실제보다 1.5~2.5배 작게 찍혀 있었음
  (합계: 기록 -$161.08 vs 실제 재구성 -$290.74, 5건 중 3건에서 과소평가).
- LIVE 모드(`close_trade()`의 `mode=="live"` 분기)는 실제 체결가(`get_fill_price()`)를
  쓰므로 이 버그의 영향을 받지 않음 - **PAPER 모드(bot1) 전용 버그**였음.

## 2. 수정 내용

### (1) 페이퍼 모드 SL 청산가 버그 수정 (`trading_service.py`, 청산 판정 블록)

`close_trade()` 호출 시 이론상 SL 목표가(`state[coin_key]["sl_price"]`) 대신 **감지
시점의 실제 `current_price`**를 넘기도록 변경. TP 청산은 원래부터 `current_price`를
쓰고 있어서 그대로 유지, SL/trend_follow Stop 4곳만 수정:

```python
# 변경 전: close_trade(coin_key, state[coin_key]["sl_price"], "Stop Loss", state, username)
# 변경 후:
close_trade(coin_key, current_price, "Stop Loss", state, username)
```

`close_trade()` 함수 자체(라이브 체결가 폴백 로직 등)는 손대지 않음 - 이미 라이브 모드는
문제 없었고, 이번 수정으로 페이퍼 모드도 "감지 시점 실제가" 기준으로 통일됨.

### (2) STALL_EXIT_CANDLES 8 → 16 (`trading_service.py`)

초반 무동력(stall) 판정 대기시간을 15분봉 8개(2시간) → 16개(4시간)로 연장. 정상적으로
천천히 붙는 추세까지 너무 일찍 SL을 조이는 걸 방지하기 위한 사용자 지시 변경.

### (3) BTC_GATE_LOOKBACK 4 → 16, 즉 1시간 → 4시간 (`price_service.py`)

2026-09-05에 15코인·1년 백테스트로 1시간이 4시간보다 우세하다고 판단해 4시간→1시간으로
축소했었으나, 사용자 지시로 다시 4시간(16캔들)으로 복원. 관련 로그 문구("BTC 1h 등락률")도
"BTC 4h 등락률"로 함께 수정(코드 동작 자체와는 무관한 표기 정정).
